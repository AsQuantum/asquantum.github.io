# 通用机器图与纯数学产率求解模型（2026-11-24）

## 1. 目标与适用范围

目标是对任意合法布局建立独立于机器编号的数学模型，不以固定的 AST1 布局、固定的分流器数量或固定的生产链为前提，不以逐 tick 仿真作为求解步骤。实际运行速率必须区分：物料守恒和容量约束允许的速率、给定明确服务规则时的数学速率、经实际有限 FIFO/轮询可达性与长期运行证明的速率。

## 2. 节点、端口、缓存、转换条件

机器是六元组 M=(I,Q_in,F,Q_out,O,S)。I 和 O 是 0 到 N 个物理输入/输出端口；Q 是无缓存、单物品 FIFO、混合物品 FIFO 或多个独立材料 FIFO；F 是转换条件；S 是共享的本地服务资源和状态（如忙碌计时、轮询位置）。FIFO 按先进先出理解，并非 LIFO 栈。

| 类型 | I | O | 缓存与动作 |
|---|---:|---:|---|
| 装饰机器 | 0 | 0 | 无物料动作；不进入物理产率图 |
| 生产机器 | 0 | 1–N | 无原料生成配方或从仓库取出 |
| 消耗机器 | 1–N | 0 | 销毁或直接存入仓库 |
| 中间机器 | 1–N | 1–N | 有时长配方、分流、合流等 |

当前实际机器语义：配方输入按材料各有 FIFO（容量为所需数量的 3 倍），多个输入口可以向同一个材料 FIFO 供料；配方输出 FIFO 容量为产量的 20 倍。分流器使用混合输入 FIFO，容量 3，输出按轮询选择，选中的不兼容过滤器会阻塞队首和指针；汇流器没有额外的每入口缓存，由 ready 输入线路队首轮询进入 3 槽共享出口 FIFO。仓入无缓存、直接入账，输入口相互独立；仓出为指定材料的 3 槽预留输出 FIFO，成功发出时扣仓库库存，同物品出口按机器数字编号预留；计算机为容量 10 的混合 FIFO，每秒销毁 1 件。以上是当前项目实现的合同，不应在数学中替换为无条件平均分配。

## 3. 物理有向多图与独立边界

一个物理生产子图允许 1–N 个生产边界，0–N 个中间机器，1–N 个消耗边界。物理图不是树，也不是必然的 DAG；允许分流/汇流链和返回边。对多输出且内部独立的生产机器，应按输出端口建立不同虚拟起点（当前没有这种多输出生产机器）；对多输入且无共享本地服务的消耗机器（当前仓入），按输入端口建立虚拟终点。如果端口之间共享内部缓存、时钟或服务带宽，不得拆成独立边界。

按边连接的公共机器资源做无向连通分组，然后保留真实有向边进行 SCC 检查。起点缺失、终点缺失、开放线路、原料缺失、孤立机器都是合法布局状况；不构成完整生产子图时单独标记，不抛弃整张图。无来源的物理回路从空 FIFO 状态不能自发生成物品；有来源和终点的物理回路不直接判零。仓入、仓出是物理边界，但由同材料全局库存形成跨图耦合，不可把仓出视为无限且独立的外部物料源。

线路 e 允许多种物品 k，各物品平均速率 x_e,k 非负。整条线总速率 sum_k x_e,k <= 1 件/秒。共享端口服务也有相应总容量。各材料不拥有独立的 1/s 带宽。

## 4. 从节点动作推导必要的长期平均方程

内部有限缓存 B 满足 B(t)=B(0)+A(t)-D(t)，B(t)/t -> 0。因此当平均速率存在时，入出守恒。配方 m 的速率 ν_m（批/秒）、时间 T_m、原料数量 a_m,k 和产量 b_m,k 满足：

```
0 <= ν_m <= 1/T_m
sum(input rates of k) = a_m,k * ν_m
sum(output rates of k) = b_m,k * ν_m
```

若配方缺少任意原料，相关入流和 ν_m 可严格为零；有效周期为无穷大。分流和汇流逐材料守恒，不能仅做总件数守恒。销毁机器总消耗 <= 服务能力。全局仓库 W_k 允许增长，不强制库存导数为零：dW_k/dt=Σdeposit_k−Σwithdraw_k>=0（有限初始库存、长期不耗尽的平均条件）。物理回流守恒 I+R=O+R 只确定 I=O，不单独确定 R。

## 5. 纯数学联立：消元和精确速率区域

设 x 为所有线路材料速率和配方周期速率，守恒方程 Hx=0。通过精确 BigInt 有理数 Gauss–Jordan 消元，得到 x=Pz，其中 z 是自由变量。非负约束、机器周期上限、共享线路/端口容量、计算机服务上限、仓库非耗尽约束构成 Az<=b，z>=0。从空初始缓存出发可额外使用材料最小不动点证明零变量，加入 x_i=0。

同一条约束涉及的自由变量划为同一代数组，仓库等共享资源会合并不同物理图。对某个指定速率或线性组合 L(x)，求 max L(Pz)，使用有理数单纯形法，Bland 规则避免退化循环；不选择权重、不最大化全厂总产率来假冒实际调度。每个上界带精确可行见证和经过校验的对偶证书。零点始终可行，故此必要区域本身不能证明非零的实际运行产率。不同目标的最大值也不一定同时实现。

## 6. 工作区间：递归最小值、轮询和优先级联立

在独立可持续输入供给和下游需求已经建立的条件下，可采用连续理想服务模型。设 c 为周期速率，s_k 为各原料的独立可持续供给，d 为输出需求，则 c=min(1/T,s_1/a_1,...,d/b)。对分流/汇流的端口速率 r_i 和独立可持续需求/供给 cap_i，理想 RR 可以写为 r_i=min(cap_i,λ)，总服务量为 min(共享服务量,Σcap_i)。对连续严格优先的仓出，r_i=min(cap_i,S−Σ_{j<i}r_j)。这里 cap_i 不是当前已实现速率本身，也不能将独立查询得到的全局上界随意当成可同时达到的局部供给。

将每个 min 等式展开为：对每个备选上限都满足不等式，至少有一个上限取等。对理想 RR 枚举端口饱和集合：饱和端口 r_i=cap_i<=λ，未饱和端口 r_j=λ<=cap_j；如果所有端口饱和则存在 λ>=max cap。递归选取活跃条件，并对每个部分分支先做精确可行性判断；不可能的整个分支直接剪去。所有可行区间均被探索时，对任意请求速率投影 min 和 max；若上下界一致，则证明在所给条件模型内该速率唯一。分支预算耗尽不能宣布唯一。

非零仿射约束 a·z<=b 的可行性：新增尺度 τ∈[0,1]，将约束改写为 a·z<=bτ，保证原点可行。词典序优化先 max τ，再 max 或 min 目标；τ=1 当且仅当原仿射工作区间可行。使用精确有理数计算，并校验词典序最优基的原/对偶证书。此步骤为数学求解，不模拟游戏运行时间。

重要边界：物理分流、合流、仓出实际执行为有限缓存、离散 FIFO、优先预留和轮询。第 6 节的工作区间仅在独立可持续供需、兼容物品以及服务规则已证明时才可作为实际模型。存在混合物品队首阻塞、相位耦合、共享原料等情形，必须从真实转换规则另外推导约束或证明，不能默认连续理想 RR 或绝对优先。没有这些规则证据时应返回必要区间和未解决的规则，而非假造唯一长期产率。

## 7. 实现接口

- `steady-machine-graph.js`：`factorySteadyCompileAbstractNetwork(layout,model)`，节点、端口、缓存、动作、物理分组、共享库存跨图关系。
- `steady-rate-region.js`：`factorySteadyBuildRateRegion(model,{forcedZero})`，消元后的精确可行域和代数耦合组；`factorySteadyRateRegionMaximum(region,terms)`，必要区域中指定线性组合的精确上界。
- `factorySteadyMinimumRegime`、`factorySteadyWaterfillRegime`、`factorySteadyPriorityRegimes`：显式条件的数学工作区间。
- `factorySteadySolveRateRegimes(region,rules,queries,options)`：递归剪枝、精确可行性、条件速率上下界与唯一性；`factorySteadyCompileConditionalRegimes(model,service)` 依据具体机器/端口及显式可持续供需参数生成规则，缺失参数时报告 unresolved。
- `factorySteadyAnalyzeMachineModel({initialWarehouseItems,service,queries})`：当前布局的统一数学入口；省略 service 时只求必要区域，不选择物理稳态。

## 8. AST1 与数学反例验证

AST1 115 台机器分为 27 个生产、44 个中间、29 个消耗、15 个装饰（分类按机器具有的物理端口，包括未连线机器），84 条有效边，12 个物理子图，22 台非装饰机器没有连接线路。27 个生产机器包括 8 台仓出。118 个独立守恒等式将 138 个速率变量消成 20 个自由变量；加容量与仓库不等式后形成 19+1 的两个代数约束组。当前必要上界中 M24 为 2/15 批/秒，M87 为 1/5 批/秒，均不被标为实际唯一产率。

验证例：混合带 A+B<=1；双原料配方同一条线需要 2A+3B 时周期速率上界为 1/5；回流图只由守恒得到 I=O，而理想满负荷且两端持续可服务的附加条件下可求出 I=O=R=1/2；1 件/秒供给、需求 1/5 与 1 的条件分流结果为 1/5 与 4/5；3/5 供给和严格优先需求 2/5、1 的条件仓出结果为 2/5 与 1/5；与容量冲突的仿射分支可严格证明不可行。

对应验证文件：`tests/steady-rate-region.test.js`、`tests/steady-generic-network.test.js`、`tests/steady-generic-bounds.test.js`。

## 9. 自动供需固定点（无需人工填写供需参数）

新增 `scripts/engine/steady-auto-fluid.js`。对当前有效机器图，为每条线路 e 建立上游可持续供给 S_e、下游可持续需求 D_e 和总实际流率 x_e=min(S_e,D_e,1)。供需均为机器局部规则的函数而非人工参数，也不把独立最大值当成同时可实现的供给。源头和终点的服务条件、配方、端口数量、过滤、共享仓库优先顺序均从布局读取。AST1 仅为测试夹具，不参加公式构造。

对于配方机，设材料 k 需要 a_k 件，产物数量为 b，周期 T。由各材料输入端口的可持续供给计算 S_k=ΣS_e。输出供给为 min(1,b/T,min_k b*S_k/a_k)。输入材料 k 的需求由 1/T、输出需求/b 和所有其他材料 j≠k 的 S_j/a_j 共同约束，再乘以 a_k；缺少原料的合法布局会自动传播零速率。多个同材料入口的分配采用明示的理想公平服务假设，不是对真实到达先后顺序的证明。

分流器入口需求为 min(1,ΣD_out)，对每个出口按输入供给和其他出口需求进行理想 RR 水位分配。汇流器出口供给为 min(1,ΣS_in)，输入需求由出口需求与其他输入供给进行水位分配。为了避免以当前已实现速率限制自身的虚假零固定点，计算单个端口的供给或需求时，将该端口自己的对向限制暂时替换为物理容量 1，再计算水位分配；最终仍取真实的 min(S_e,D_e)。这样在其他支路需求变化时能够重新分配，不冻结第一次分流结果。

仓库按物品汇总所有入库速率；每个仓出按机器优先序得到当前剩余供给，扣除本出口实际能发出的速率后再分配给下一台。未取出的剩余物料积累于仓库。此规则属于连续严格优先的理想模型；真实 3 槽预留 FIFO 在补货与释放不同相位时仍需另证。

求解过程对全网 S、D 联立执行数值不动点迭代（迭代次数不是游戏时间、不是逐件或逐 tick 仿真）。分别从低供给和高供给两种初猜开始，收敛后尝试恢复有理数，再用 BigInt 精确重新计算所有供需等式、配方守恒、逐材料分合流守恒、线路容量和仓库非耗尽；任何不一致都拒绝输出。两种初猜必须得到相同的实际速率向量才发布条件解。两种初猜一致并不是全局唯一性证明。

混合线路：允许汇流后的混合线路流向其他汇流器或无条件兼容的消耗终点，逐材料率由上游守恒推出。混合线路直接进入配方或分流器时，物品顺序可能改变吞吐；选中过滤器的队首阻塞、未知共享缓存仲裁、正流量混合循环等均明确报告未解，不把混合材料当作独立带宽。空初始缓存且无可达物料的线路先证明为零。开放线路不持续消耗物料。

接口：`factorySteadyAutomaticFluidModel()` 自动编译；`factorySteadyAutomaticFluidBudget()` 生成精确验证的条件收支和机器/线路速率。该结果作为 `warehouseTheory().conditionalBudget` 独立于原认证结果；面板仅在固定点校验成功时显示，并明确注明“条件解”，原 `diagnostics.certified` 不会因此变为 true。旧的 AST1 特定条件诊断不再进入通用运行时求解。

验证：`tests/steady-auto-fluid.test.js` 包含独立多原料、分流后需求再分配、级联分流、带源及无源物理循环、混合汇流尾线、共享仓出优先级、缺原料停机、混合 FIFO 未解以及 AST1 回归。AST1 条件结果钛合金锭入 80/min、出 71/min、净增 9/min；仅为通用模型输出与测试参考，不是该算法的输入或硬编码约束。

当前结论：自动供需建模和理想连续固定点求解已实现；离散 FIFO/轮询的全局可达性、稳定性、唯一性及所有合法混合图的精确实际产率仍未证明。条件结果可用于对照真实长时间收支，不能误标为已认证的真实稳态。

## 10. 当前稳态的潜在库存缺口

理论收支第四列“实际净值”不是不限库存的新全局稳态。保持已求得的受限稳态收入 I_k 和其余供需状态不变，读取每个仓出对应线路的当前下游需求 D_e；定义 N_k^*=I_k−Σ_{e∈仓出_k}D_e。仓库实际支出为 Σ min(S_e,D_e)，所以原本库存富余的物品不改变净值，而库存约束造成的零净值可能显示为负值。即使从空状态无法产生物料，结构有效的仓出仍可具有非零下游需求；零供给证明不等于零需求。这是基于当前条件模型的需求快照，而非重新求解后的长时间实际产率；不保证所有潜在需求可同时持续实现。

## 11. 透支净值与机器周期显示

第四数值列为潜在净值（第10节）；第五数值列为透支净值：解除所有仓出库存限制，允许全局仓库净值为负，重新求解全网络的另一个供需平衡点。两个模型均保留机器配方、物料守恒、带宽、下游需求和局部调度假设。透支净值只用于仓库需求分析，不改变受限稳态的机器有效周期、线路速率或实际模拟库存。Canvas和属性面板读取受限稳态结果，完整认证结果优先，其次为精确校验的条件固定点；无解时保留未知标记。

## 12. 正式运行入口与最终验证

正式页面只加载通用守恒方程、物料可达性、必要上界、精确有理数公共函数和 `steady-auto-fluid.js`。 `warehouseTheory()` 直接编译当前布局并运行自动供需固定点；普通稳态与透支稳态复用同一个方程模型，不再先运行旧的递归算法。旧 AST1 专用工作区间模块已经删除；历史限制求解器和旧诊断展示仅作为独立离线参考测试保存在 `tests/support/legacy-rate-reference.js`，不进入网页。其他通用证明工具保留给独立数学验证。未知布局不会伪造零产率或改用旧算法。

最终验证：六种独立小图（分流反压、多原料、级联分流、混合汇流尾线、仓库优先级和物理回流）使用原逐件模拟器各预热 20 分钟并独立统计 60 分钟；所有仓库收支和逐台机器逐材料输入/输出的计数均与条件模型预测一致。完整 AST1 及删除 M89 后的蓝图各验证 180 分钟（每 60 分钟记录），末小时最大收支误差分别为 0.0167 和 0.0333 件/分钟。AST1 只作为测试夹具，重编号后重新求解得到相同产率。通用模型仍不宣称已证明任意混合 FIFO、阻塞与相位耦合图的实际唯一稳态，未解布局保留未知结果。
