# 任意生产—转运—消耗图：共享资源行为方程研究

2026-11-24。补全正式规范中的行为约束，不替代平均流率求解器。本研究没有固定时间步长、逐件时间模拟、LP 或产量最大化目标。按用户要求不使用特定蓝图的机器编号或期待产量作为方程。

## 1. 问题的通用抽象

工厂物理图仍由机器、端口、线路、仓库组成。将每个有限缓冲区及独占加工资源表示为资源节点 p（容量 C_p、物料约束、初态）；将每个允许的机器动作表示为转换 a（消耗向量 u_pa、产生向量 v_pa、冷却、延迟、选择规则）。同一共享资源连接任意数量的转换，而不是给每条路线复制一个缓冲区。加工、生成、分流、汇流、消费只是在此抽象中具有不同的转换定义。

用 N_a(t) 表示截至连续时间 t 的累计成功动作数。有限资源数量：

    B_p(t)=B_p(0)+Σ_a(v_pa-u_pa)N_a(t)
    0≤B_p(t)≤C_p

因此任意有限资源满足平均守恒：

    Σ_a(v_pa-u_pa)r_a=0

这里 r_a 是动作长期平均发生率。它不包含资源释放时的选择信息，因此存在共享输入、输出或仓库竞争时，平均守恒和容量约束可能不足以确定所有目标。这是一个一般的共享资源冲突问题，不是某种冶炼炉的专用问题。

## 2. 连续事件代数

对于一个假设重复的有限事件顺序 w（不是实际模拟时间序列），周期 H、事件相位 φ_j，定义跨周期发生时间：

    t(j,k)=φ_j+kH

各资源的占用可由 w 的前缀累计增减直接计算。所需第 n 个 FIFO 令牌的产生序号可由累计生产/消费与周期初占用直接定位，包括来自先前周期的令牌。用产生相位、周期偏移和固定延迟确定该令牌的就绪时间。

在当前符号事件前，结构上可执行的转换 a 必须具有足够物料和空位。其最早就绪时间 E_a 为上一事件时间、上次同转换时刻加冷却及所需令牌就绪时刻的最大值。下一事件时刻由实际工作守恒确定，而非人为目标：

    E_a=max(前一事件时刻, 冷却截止时刻, 所需令牌的就绪时刻)
    t_next=min_a E_a

选择的动作必须在此时刻可执行；竞争组中更高优先级动作若同时就绪，不允许较低优先级动作先执行。在周期假设下，上式可自动变成现有直接有理数求解器可读的分段仿射方程。每个动作每周期次数 c_a 确定时，长期率 r_a=c_a/H。

## 3. 实现边界

periodic_resource_algebra.js 是第一版通用有限同物料 FIFO 资源原型。输入为资源、转换及一个符号周期事件顺序；输出为精确周期、可行候选动作率及优先级验证。检查同一周期的资源增减平衡、前缀容量、令牌序号、固定传输延迟、转换冷却与最早服务方程。

对于几何优先级，当前先求非严格方程，再验证高优先级动作的就绪时间差。如果差值已被证明唯一且≤0，则整个候选顺序违反优先级；若只发现某个候选相位违规而未证明差值唯一，返回未确定，不排除其他相位。无穷大仓库漂移、混合 FIFO 颜色顺序、依赖 RR 指针的跳过/阻塞、传送带连续位置和全部生产转换的自动编译仍待完善。

最重要的未解问题是如何自动确定符号重复顺序及初态可达性，并证明任意真实网络的目标长期率。不能因为一个给定顺序具有精确周期就认定实际运行一定选择该顺序。也不能从平均周期推导最短实际开工间隔。普通定时事件图及同步数据流的无冲突结构方法可借鉴，但游戏存在实际资源竞争，不能将外部的最大吞吐优化问题作为本项目的真实运行问题。

## 4. 本次验证

test_periodic_resource.js：
- 45 种不同入口数/批次规模的共享资源方程验证。
- 1/4/12/24 层串联图，含精确运输延迟，求得正确周期。
- 16 个固定随机种子生成的有向无环资源拓扑，包含多输入和多输出，精确周期 7/3 秒。
- 对 3 个空位、两入口、4秒批次的抽象资源，检验一个批次内所有8种输入事件顺序。最早服务条件排除4种，严格优先级差值证书排除3种，余下右/左/右，周期4秒，输入流率1/2及1/4件/秒。不是物理八机蓝图已经求解，也没有证明所有多批次周期均被排除。

这些是抽象资源模型测试，不能视为任意合法游戏蓝图的求解验收。无手工蓝图特例。正式 HTML 仍使用原直接平均流率求解器。原8台机器的矿石入库未知未修复；进一步研究应先将真实设备统一编译成资源动作，并仅对确实导致目标不唯一的竞争子图补充可证明约束，保持普通图快速求解。
