# 多件批次反压：有限序号图的严格上下界定理

本定理继承 cadence-backpressure-proof.md 的理想连续时间工作守恒语义、合法同物品 FIFO 传送带、端口冷却 P、间距 s、速度 v、P≥s/v。不是 HTML 逐帧语义的等价性定理。生产机唯一成品输出，所连接的下游该物品只有这一个输入线路，初始该输出队列、该传送带及下游该物品缓存为空。其他配方输入只要求有已经逻辑证明的供给上界。证明不读取模拟、实际产量或既有速率解。

## 1. 参数与正向供货证明

上游每批产 b 件，标称加工时间 T，成品缓存 C≥b。下游每次开工消耗 q 件该物品，原料缓存 D≥q。物料数量均为正整数。对于上游配方每种原料 k，选取已证明的供货间隔上界 G_k（指在需要时，下一件在上次接收或开工后持续等待的最迟就绪保证，不是平均速率倒数），每批需要 n_k 件。定义

    F=max(T,max_k n_k G_k).

因为开工消耗原料后，若原料仍不足则其缓存尚有空间，指定入口至多 n_k G_k 秒即能提供需要的物料；其他入口不会减少已进入共享缓存的原料。所以，在上游产物不受阻时，下一批开工不晚于上次开工+F。配方产出 b>1 不改变这一论证。

上一件成功发送后，若仍有成品，则下件已就绪；若没有而加工尚未结束，T 秒内有产物；若没有且机器空闲，则上一批已完成，上一批开工≤上次发送−T。下一批所需原料不晚于上一批开工+F准备好，且此时空成品队列允许下一批开始。由此，单个产物供给的保守最长间隔 B=max(P,F) 仍然成立。它不一定是最紧的上界；尤其不能把 F/b 当成单件最长供给间隔。利用同物品传送带序号约束可将 B 传播为接收端供货间隔上界。兼容分流、汇流的供给上界仍采用前一证明的充分条件；未证明的供给不能自我循环认证。

若下游某个加工机的唯一产物线路直接通往无限制仓入，T≥bP 且每种原料都有已证明入口满足 n_k G_k≤T，则初次开工后每批原料在下一次允许开工前补齐，每批 b 件产品能在下一次完成之前发送。其实际开工节奏严格为 T。这里允许原料具有多个入口，因为只需证明其中一个足以满足全部需求；额外入口的物品不减少缓存。

## 2. 单条生产连接的通用序号不等式

令 A_i 表示上游第 i 批开工，S_j 表示第 j 件产物发送入带，R_j 表示该件被下游接收。编号均从0开始。设 L 为带长，L/s 是正整数，K=L/s+1，d=s/v，a=L/v。令 Q_i 为下游第 i 批实际开工。忽略初始尚无相关序号的前缀。

上游开工的下界：

    A_i ≥ max(A_(i−1)+T, S_((i+1)b−C−1)).

原因是上次加工必须结束；开始这一批时，预留 b 件成品空间，既有 (i)b 件成品中至少已经发送 (i+1)b−C 件，编号为 (i+1)b−C−1 的发送因此是必要条件。由 F 的原料保证及工作守恒，上界是

    A_i ≤ max(A_(i−1)+F, S_((i+1)b−C−1)).

这不是平均供需方程，而是由实际有限输出缓存约束推导的序号不等式。

同物品带的发送与接收：

    S_j = max(S_(j−1)+P, R_(j−K)+d, A_floor(j/b)+T),
    R_j = max(R_(j−1)+P, S_j+a, Q_floor((j−D)/q)).

发送式三项分别是端口冷却、空间与已加工完成的该件产物。接收式三项分别是冷却、运输、共享原料缓存的可用容量。这里该物品只有一个入口，故没有接收容量竞争。初始空缓存可先接收 D 件，之后每次下游开工释放 q 个位置，恰好得到 Q 的序号项。无需另外假设传送带或输入/输出缓存已经满载。若起始库存非空，要调整编号与初始令牌数，不能直接照搬。

传送带项的推导：第 j 件到终点的最早时刻是 max(S_j+a,R_(j−1)+d)；若前件尚未离开注入点至少 s，不能发送新件。考虑沿传送带的自由运动和前件阻挡，每个已接收的前件 h 对当前位置 z 的限制在 z>L−(j−h)s 时为 R_h+(z−L+(j−h)s)/v。由于相邻接收间隔≥P≥d，最后一个满足该条件的前件约束支配更早前件。对于第 j−1 件到达 z=s，得到 max(S_(j−1)+d,R_(j−K)+d)。冷却 P 支配 d。因此上述 S、R 方程精确。连续语义中同一物理时刻释放的位置允许即时重新判断，不人为加入一帧延迟。

## 3. 下游周期包络及最小公共序号块

设已证明下游开工序列具有有限启动期后的周期包络：

    Q_(km+h) ∈ [kH+ell_h, kH+u_h],  h=0..m−1.

H 为周期块时长，m 为块内开工批次数，ell/u 是固定有理相位上下界（可含一个共同时间原点；不要求两者相等）。当 ell=u 时，就是精确的周期事件序列。

一个下游周期块需要 M=mq 件物品。取 J=lcm(b,M)，则对应上游 N=J/b 批，下游经过 J/M 个周期块，总时间 W=H*J/M。构造有限相位图，共 N+2J 个事件变量：N 个 A 相位、J 个 S 相位、J 个 R 相位。每个上节不等式中的前件序号按模 N 或 J 映射至相位节点，跨越一个先前周期块的边权减 W（跨 k 块减 kW）。下游 Q 项变成每个 R 相位的固定下界/上界锚点。

分别以 T 和 F 作为 A_i←A_(i−1) 边权，构建下界图和上界图。所有其他边权相同；下界图权重≤上界图权重。两图完全由机器参数、带长、缓存、已证明供货上界及下游节奏包络决定。

## 4. 核心定理及证明（不是实验）

若上界相位图的每个有向非空回路的权重和严格小于0，且所有事件节点都可由外部锚点到达，那么：

    L_v = max_(anchor h → v)(ell_h + 路径下界权重和),
    U_v = max_(anchor h → v)(u_h + 路径上界权重和).

这些最大值一定由无重复节点的简单路径取得，因为移除负权回路会严格增加路径权重。因此每条候选路径最多 V−1 条边，V 是相位节点数。它们可以通过有限图上的有理数最长路径代数直接计算，无需时间推进或数值收敛。

证明实际事件最终满足该包络：把实际事件时间减去相应块序号乘 W，记为归一化相位。将序号不等式沿因果依赖展开为路径。任意有限简单锚点路径在足够大的块序号上完全位于已证明的下游包络区间，直接推出实际相位≥L_v。对于上界，展开直到遇到锚点或有限初始前缀。锚点路径的权重不超过 U_v−对应锚点值；而通向初始前缀的路径，随块序号增加其最短可能长度趋向无穷（每条边最多跨有限个序号块，同块内因果关系无环）。有限图上的长路径必含越来越多的简单回路。因为所有简单回路严格为负、数目有限，存在统一正数 ε，使每个简单回路至少减去 ε；除去回路后剩余简单路径的权重有统一有限上界。因此来自初始前缀的所有候选上界项一致趋向负无穷，有限时间后必小于 U_v。故实际归一化相位最终夹于 L_v,U_v。证明只使用不等式和有限路径分解，没有执行逐件递推。

于是上游开工 A_(kN+h)∈[kW+L_h,kW+U_h]，直接得到

    ν = lim_(t→∞) N_start(t)/t = N/W = mq/(bH).

证明：固定有限相位宽度意味着累计开工数与 t*N/W 的差有界。这个结论不要求每次实际开工间隔相等。若所有 A 相位的 L=U，则有限启动期后精确重复该加工节奏；否则得到有界但未必重复的实际相位。

加工最短间隔的可靠下界为

    H_min=max(T, min_h(L_(h+1)−U_h)),

末项 L_N=L_0+W。它可直接用于共享原料补料对齐不变量。不能使用平均周期 W/N 代替 H_min。

因为输出仍是相同形式的周期包络，定理可以继续沿任意深度的符合条件的上游连接传播；即使 L≠U，也不必中断。非负回路（含零）只代表这个严格衰减证明不足，不能判定实际网络不生产或不具稳态。对无锚点的循环同样拒绝。分支、多个物品输入可以存在于正向有根供给证明中，但上述逆向容量方程不覆盖同一物品多个供给共享的接收序号、多个竞争成品出口或无独立供给的循环。

## 5. 实现与验证

研究实现：
- batch_backpressure_bounds.js：有理数相位图，利用词典序(权重,边数)检查非负回路，负回路下的有限最长路径；返回证明的平均率、最短间隔和相位包络，或明确未证明原因。240相位节点为实现资源保护阈值，不是定理限制。
- general_batch_cadence.js：正向证明每条同物品供给上界，建立直接入库的终端节奏，逆向传播上述包络，并使用已证明的 H_min 和供给上界验证共享输入对齐。研究 compile_exact.js 可接收已证明机器率及补料等式；不改变正式 scripts/engine/ 中的代码。

原8机反例自动得到矿石3/4件/s，所有查询值唯一。改变上游/下游批次数量的符号图以及 10 组不同批量、带长、缓存、节奏参数验证了实现；有一组临界零回路被拒绝。例：b=2,q=3,H=9,T=2,F=3，得到 W=18,N=3，ν=1/6，H_min=2（不是6），开工相位仍有上下界差异；b=3,q=2,H=8 时 W=24,N=2，ν=1/12，最短间隔9，另一间隔15，严格周期序列。非固定时间格的有理参数和24层非精确相位包络传播也通过回归。两份大型真实蓝图原有基础条件解不变，但新证书并未覆盖这两份图，不能将其当作新定理的验证对象或全图已证明。

本定理是充分条件，绝非任意实际工厂图的完备求解器。没有解决共享出口、多路同物品竞争的一般实际序号关系，也未证明所有循环的长期极限。实验测试仅验证代码实现，不承担逻辑证明。仍未接入正式HTML。
