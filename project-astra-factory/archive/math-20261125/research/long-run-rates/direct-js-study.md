# 2026-11-24 纯 JS 直接联立求解进展

## 实现与验证
- compile_exact.js：精确分段速率方程，常量折叠、公共表达式共享、区间支配剪枝。
- direct_algebra.js：BigInt 有理数 Gauss–Jordan、有限符号工作区间、精确剩余不等式消元、逐目标唯一性；每个可行分支回代所有原始断言。高耦合变量优先只改变符号搜索顺序，不改变模型。
- direct_graph.js：独立读取真实布局、仓库、冻结配置；不调用旧固定点求解器。逐项返回精确字符串或 null（未知）；净值、总计、本地净值、机器/线路合计分别作为独立代数目标。
- direct-worker.js、test_browser_direct.js：普通本地静态 HTTP、真实 Edge Worker，无跨源隔离，无 Python、WASM、旧数值求解器。三份真实蓝图受限/透支全部成功，浏览器测得整次 219/442/286ms（72/73/115 台）。曲速线圈净速率分别 1/128、1/99、11/1440 件/s；115 台透支 1/80 件/s。
- 历史 36 个去重场景：33 个条件解、3 个正确未解，fair 与 relaxed 策略均通过，唯一分数与已有参考相符。公平策略仅用于与历史模型对照，不默认应用于普通配方入口。
- 以上仅证明连续条件模型，不能当作任意离散调度真实长期解的定理。

## 实际合法布局反例
legal-shared-input-branch.json：共享同物品入口可影响合金板收入与支出，但净值 3/2 件/s 和线圈净值 1 件/s 在放宽入口模型内唯一。未知收入/支出不能当 0；独立总计也可能比各组成项更容易确定。
legal-net-branch.json：真实两采矿机、分流、冶炼炉、复合装甲板组装、冻结合金供给；七条合法线路。矿石净值公平模型 5/8 件/s（37.5/min），长期绝对优先 1 件/s（60/min），HTML 模拟预热20分钟、统计60分钟为 3/4 件/s（45/min）；装甲净值均 1/4 件/s（15/min）。放宽入口模型正确识别矿石净值不唯一；仍不能证明它包含任意物理调度的所有实际速率。

## 局部批次补料定理（历史记录，现以 direct-inlet-proof.md 的连续时间证明为准）
设同材料缓存每批释放 q 个槽位、n 个入口按右到左排序，且每次补料开始前缓存满，每一轮所需端口均已就绪、均有相同冷却 P，最短加工间隔 T≥ceil(q/n)P，补料轮次在相同事件阶段开始。按完整轮次及最后不满的一轮直接计数：第 i 口（i从0起）每批接收 floor(q/n)+[i<q mod n]。于是该口长期速率等于此整数乘配方批次率。无需枚举每件物料或推进时间。
在 legal-net-branch 的冶炼 q=3,n=2,P=1,T=2，若上述前提成立，右2左1。联立可得右1/2、左1/4、矿石净值3/4件/s，与60分钟实测吻合。
编译器有可选 batchRefillCertificates 参数；必须由独立就绪证明授权，当前仅作为条件定理实验，默认不会自动启用。长期稳定满缓存和所有相关入口及时就绪的结构证书尚未完成，不把观测值当证书。一般多材料、混合 FIFO、非同步/间歇供应仍需进一步研究。

## 接入边界
纯 JS 浏览器运行能力已验证，正式 HTML 未替换旧求解器。当前正式 UI 对缺省字段用0，不能直接接收逐项未知；实际共享入口竞争已证明会影响仓库结果。必须解决相关服务区间的可达性及适用条件，或明确限定已证明的子情形，避免把条件解误标成实际解。两个布局搜索器未改；未提交。
